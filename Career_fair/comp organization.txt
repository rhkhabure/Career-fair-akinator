1. Interrupts and RISC Architectures
a) Definition and Classes of Interrupts (8 marks)
Definition: An interrupt is a signal generated by hardware or software to alert the processor of an event that requires immediate attention. It temporarily halts the current program execution, allowing the CPU to execute an Interrupt Service Routine (ISR) before resuming normal operations.

Three Classes of Interrupts:

1. Hardware Interrupts: These interrupts are triggered by external devices (such as keyboard presses, mouse movements, or the completion of disk drive I/O) to notify the CPU that they require attention.
2. Software Interrupts: These are generated internally by the execution of specific instructions within a program, often employed to request services from the operating system (known as system calls).
3. Internal Interrupts (Exceptions): These occur due to errors during program execution, such as division by zero, invalid opcodes, or page faults.

b) Characteristics of RISC Architectures (8 marks)
Streamlined and Limited Instruction Set: Utilises a concise set of straightforward instructions, facilitating faster decoding and execution.
Load/Store Architecture: Memory access is confined to designated LOAD and STORE instructions, with arithmetic and logical operations performed exclusively on registers.
Fixed-Length Instructions: Instructions are generally uniform in size (e.g., 32 bits), simplifying instruction fetching and decoding.
Abundant Register Availability: Focuses on high-speed, general-purpose register files to reduce the frequency of accessing slower main memory.

2. Benefits of RISC over CISC (4 marks)
Enhanced Execution Speed: Streamlined instructions enable execution in a single clock cycle, improving overall performance.
Optimised Hardware Design: The reduced instruction complexity requires fewer transistors in the control unit, thereby reducing manufacturing costs.
Improved Pipelining Efficiency: Consistent-length and straightforward instructions facilitate pipelining, leading to increased throughput.
Lower Power Consumption: The compact, simpler chip designs produce less heat and consume less power, making them particularly well-suited for mobile and battery-operated devices.
3. Instruction Cycle States and Interrupts
a) Instruction Cycle States Diagram (14 marks)
The instruction cycle (fetch-decode-execute) represents the fundamental process of instruction execution.
  


Discussion of the States
1. Instruction Address Calculation (IAC)
Purpose: The processor determines the memory address of the next instruction to be fetched.
Mechanism: Usually, this involves adding a fixed number (the instruction length) to the current Program Counter (PC) address

2. Instruction Fetch (IF)
Purpose: The CPU reads the instruction from its specific memory location into a processor register (the Instruction Register).
3. Instruction Operation Decoding (IOD)
Purpose: The CPU analyses the fetched instruction to determine what operation needs to be performed (e.g., ADD, SUB, LOAD) and what data (operands) it requires.
4. Operand Address Calculation (OAC)
Purpose: If the instruction requires data from memory or an I/O device, the processor calculates the address of that operand.
Multiple Operands: Notice the loop between this stage and "Operand Fetch." This indicates that if an instruction requires more than one data item, the calculation and fetch steps are repeated.
5. Operand Fetch (OF)
Purpose: The CPU retrieves the necessary data (operands) from memory or an I/O module.
6. Data Operation (DO)
Purpose: This is the core "Execute" phase. The Arithmetic Logic Unit (ALU) performs the actual operation (mathematical, logical, etc.) on the fetched operands.
7. Operand Store (OS)
Purpose: The result of the operation is written back into a memory location or sent to an I/O device.
Multiple Results: Similar to the fetch stage, if the operation produces multiple results (like in certain complex instructions), it may loop through the address calculation and store phases again.

Key Feedback Loops in the Diagram
Return for string or vector data: This loop allows the processor to process blocks of data. After a single data operation, if more elements in a "string" or "vector" need processing, it returns to the operand address calculation stage rather than fetching a new instruction.
Instruction complete, fetch next instruction: Once the final result of an instruction is stored, the cycle resets to calculate the address for the very next instruction in the program sequence.



b) Three Interrupts in the Instruction Cycle (6 marks) 
I/O Interrupt: Occurs upon completion of an Input/Output operation, signalling that data is ready.
Timer Interrupt: Triggered by a timer within the processor, often used for operating system time-slicing and task scheduling.
Hardware Failure Interrupt: Signals critical failures such as power loss or RAM errors, requiring immediate CPU intervention. 

4. MIPS ISA Facilitation of Pipelined Execution (4 Marks)
Fixed-Length Instructions (32-bit): Allows the fetch stage to easily know where the next instruction begins, enabling efficient parallel fetching.
Load/Store Architecture: Separates memory access from register-based arithmetic, ensuring ALU instructions do not need to wait on memory operands.
Three-Operand Format (e.g., ADD R1, R2, R3): Simplifies register reading (two sources) and writing (one destination) within a single cycle.
Simple Register Addressing: Regularised instruction encoding speeds up the Instruction Decode stage. 

5. Interrupt Handling Scenario (8 MARKS)
i. Sequence to Preserve State:
CPU finishes the current ALU instruction.
Save the current Program Counter (PC) onto the stack.
Save the Program Status Word (PSW/Flags) onto the stack.
Disable interrupts (prevent nested interrupts if necessary).
Load the address of the Disk Drive handler from the IVT.
 
ii. Interrupt Serviced First & IVT Role:
Serviced First: The Disk Drive (High Priority) interrupt will be addressed first, given its higher priority relative to the Keyboard interrupt [Scenario description].
IVT Role: The Interrupt Vector Table (IVT) is a memory structure that contains the starting addresses (vectors) of Interrupt Service Routines (ISRs). When an interrupt occurs, the CPU references the interrupt number to access the IVT and locate the address of the corresponding Disk Drive handler.
iii. "Program Status Word" (PSW) during transition:
The PSW (which contains condition codes and status bits) is pushed onto the system stack to save the "context" of the high-priority calculation, ensuring the calculation can resume correctly after the ISR finishes. 

6. Reasons I/O Devices Cannot Be Directly Connected to the System Bus (3 marks)
Speed Mismatch: Peripherals (e.g., keyboard) are significantly slower than the CPU/memory, which would tie up the high-speed bus unnecessarily.
Different Data Formats: I/O devices often use different data formats, voltage levels, or word lengths (e.g., 8-bit serial) compared to the system bus (e.g., 64-bit parallel). 


7. 4-Stage Pipeline and Data Hazard (7 Marks)
Pipeline Stages: Fetch (IF) 
Decode (ID) 
Execute (EX) 
Write-back (WB).
Data Hazard Scenario (Read-After-Write):
I1: ADD R3, R1, R2 (Writes to R3 in WB)
I2: SUB R5, R3, R4 (Reads from R3 in ID)
Illustration:
Cycle 3: I1 is in EX, I2 is in ID. I2 reads R3, but I1 has not written the new value yet.
Result: Data Hazard (RAW). I2 reads stale data.
Solution: Insert a stall (bubble) or use forwarding. 

8. Boot Process Facilitated by BIOS (4 marks)
Power On/POST: Power is supplied, and the CPU runs the Power-On Self-Test (POST) to verify hardware components.
BIOS Initialisation: The BIOS searches for the boot loader on storage devices (hard drive/USB).
OS Loader Loading: The BIOS loads the Operating System's Master Boot Record (MBR) or boot loader into RAM.
Transfer Control: The BIOS transfers control to the OS loader, which then takes over the system. 



9. Differences: Dual-Channel vs. Quad-Channel RAM (6 marks)
Memory Channels: Dual-channel uses two 64-bit channels (128-bit total), while quad-channel uses four 64-bit channels (256-bit total), offering twice the bandwidth.
Performance: Quad-channel delivers superior memory throughput, making it ideal for workstation tasks (3D rendering, 4K video) compared to dual-channel.
Compatibility/Cost: Dual-channel is standard on mainstream systems, whereas quad-channel requires specialised high-end motherboards/CPUs and four matching modules.
